# Luma（流明）开发需求日志

> 记录创始人明确要求过的需求、以及踩过的系统坑。改这个项目前先读这里。

## 需求清单

1. **每块屏独立亮度**，一条滑块一块屏，互不影响；
2. **面板按真实摆放显示**：读 `NSScreen.frame` 画「屏幕地图」，不是竖排列表；
3. **当前屏幕高亮**（点哪块屏的图标，哪块屏的瓦片高亮）；
4. **弹框挂在菜单栏下方**，不能盖住状态栏；
5. **弹框里瓦片和边框之间要有留白**（14pt）；
6. **睡眠唤醒 / 显示器插拔后尽快恢复亮度**，不能先亮一段时间；
7. **12 种语言**，入口放在面板右下角（地球按钮）；
8. 开机自启、赞助入口（二维码），不强制、不打扰。

## 系统约束与踩坑（血泪）

1. **毛玻璃**：`NSVisualEffectView` 自己设 `cornerRadius` + `masksToBounds` 会**直接废掉 blur**，
   退化成一块灰底。正确做法：外层 NSView 负责圆角裁切，内层放 NSVisualEffectView。
2. **自绘 borderless 窗口拿不到系统 popover 材质**。要苹果那种质感，就用 `NSPopover`。
3. **NSPopover 的窗口高度包含顶部箭头（约 26pt）**。按「窗口顶 = 屏幕顶」定位会**盖住菜单栏**
   （实测被用户骂过）。要按 `屏幕顶 - 菜单栏高度 - 窗口高度` 定位。
4. **accessory app 上 `popover.behavior = .transient` 不可靠**（会自己乱关）。
   用 `.applicationDefined` + 全局点击监听自己关，并跳过菜单栏点击（那是图标 toggle）。
5. **gamma 软件调光要「重绘探针」**：gamma 表写进系统后，如果那块屏画面静止，
   WindowServer 不会把新表推上去。要在屏幕角落放 2×2 黑色小窗口抖 1 像素逼一帧。
6. **唤醒恢复必须多轮补写**：唤醒瞬间显示器可能没就绪，系统还会在稍晚再重置一次 gamma。
   按 0.05 / 0.12 / 0.3 / 0.7 / 1.5 / 3 / 5 秒各恢复一次，每次带读回校验。
7. **必须单实例**（flock）：两个实例同时写亮度会互相打架。
8. 状态栏图标按屏幕数量动态画、当前屏实心；菜单栏图标不要用模板图（tmplate 会丢颜色）。

## 提问协议（动手前先问）

1. 不装这个软件时，你现在要做什么动作？（点图标？拖滑块？）
2. 你希望**看到**什么变化？用可观察的判据说。
3. 其他屏/其他窗口允许变化吗？
4. 你说的「X」是指哪个具体对象？（亮度 vs gamma；弹框 vs 窗口；聚焦 vs 激活）
5. 你描述的是**亲眼看到的现象**，还是**推测的原因**？

## 交付标准

- 改完必须自己截图看；「编译通过、装上了」不算做完；
- 弹框位置、留白、按钮边距这些，用像素量，不靠感觉。
